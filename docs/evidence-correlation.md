# Evidence Correlation

## 1. Investigation Scope

This document correlates the findings from the initial traffic triage and suspicious activity investigation of `01-c2-beaconing.pcap`, using `04-baseline-clean.pcap` as a behavioral reference.

The captures are synthetic training datasets. The analysis does not establish a real-world security incident.

## 3. Correlation Analysis

### 3.1 Primary Communication Pattern

E01, E02, E03, and E04 reinforce one another.

The repeated destination, approximately one-minute interval, consistent session structure, and recurring request-response exchange collectively support the interpretation of automated periodic communication.

This behavior is consistent with beaconing. However, periodicity alone does not establish malicious intent.

### 3.2 Payload and Protocol Characteristics

The client sends a different payload in each session, while the server returns the same payload in all 14 sessions.

This asymmetry is an observable pattern, but the available data does not establish whether the client messages contain telemetry, identifiers, commands, encrypted data, or another type of information.

The TLS-like headers do not provide sufficient evidence to confirm a conventional TLS negotiation or identify the application protocol.

### 3.3 Isolated Connection Attempts

The six isolated SYN packets originate from the same internal host as the primary communication pattern.

However, they target different destinations and have no corresponding replies in the capture. No evidence establishes that they are generated by the same process or serve the same purpose as the periodic sessions.

They are therefore treated as a separate group of events.

### 3.4 Baseline Comparison

The supplied baseline exhibits short TCP conversations with different destinations and DNS queries over UDP.

The investigated capture instead contains repeated sessions to one destination, with recurring payload exchanges.

This comparison supports a behavioral distinction between the datasets. It is not a controlled comparison and does not independently establish malicious activity.

## 4. Alternative Explanations

The observed behavior may be consistent with:

- A legitimate monitoring or telemetry agent communicating periodically.
- A proprietary client using a fixed request-response pattern.
- A synthetic protocol or behavior designed for the training scenario.
- Malicious automated communication, including beaconing.

The available evidence does not distinguish conclusively between these explanations.

## 5. Confidence Assessment

| Assessment | Confidence | Rationale |
|---|---|---|
| Repeated periodic communication exists | High | Fourteen sessions and measured intervals support this directly. |
| The primary communication is automated | High | Consistent timing and session structure support this interpretation. |
| The behavior is consistent with beaconing | Moderate to high | The observed pattern matches common beaconing characteristics, but benign alternatives remain possible. |
| The six isolated SYN attempts are related to the primary pattern | Low / undetermined | Only the source host is shared; no causal or process-level relationship is established. |
| The traffic is malicious | Undetermined | No sufficient evidence establishes malicious intent or compromise. |

## 6. Limitations

- The datasets are synthetic training captures.
- `203.0.113.77` belongs to the TEST-NET-3 documentation range and is not evidence of a real command-and-control server.
- The available payloads do not reveal the purpose of the communication.
- A conventional TLS handshake was not established.
- No process-level or endpoint telemetry is available to attribute the connections to a specific application.
- The absence of a response in the capture does not prove that a destination was unavailable.
- The baseline is a reference dataset, not a controlled experiment.

## 7. Correlation Conclusion

The strongest correlated finding is a repeated, approximately one-minute outbound communication pattern between `10.0.5.23` and `203.0.113.77:443`.

Its timing, session structure, and recurring request-response characteristics are consistent with automated beaconing behavior.

The six isolated connection attempts remain separate, uncorrelated events. The available evidence does not establish malware, command-and-control activity, data exfiltration, or host compromise.

Further attribution would require additional evidence, such as endpoint process telemetry, application context, or a more complete and interpretable protocol capture.
